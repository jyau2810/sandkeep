# 验收记录

用户已认可细砂瓶子的效果。本轮修正倒沙时整块照片砂体消失的问题，让临时颗粒经过瓶口、落到局部沙堆并向下与两侧铺开，同时优化装瓶并删除多余文案。测试与独立复核不代替用户对新界面和动效的视觉评价。

## 构建与运行

- `npm run build` 通过 TypeScript 检查并生成静态产物。
- 生产预览从 `/sandkeep/` 子路径加载，字体、示例和 HDR 资源正常。
- 1440px 桌面、390px 手机模拟和用户实际面板宽度 590px 均有实际截图，没有横向溢出或页面错误。
- 三种宽度的完成态画框均保持 5:3，没有透视变形。倒沙和装瓶均有四个时点的实拍，并有正常速度实际操作录屏。第一轮发现偏黑颗粒、螺旋分层和分块铺沙，修正后重新采集确认。本轮独立 Impeccable 复核结果为 `ship`，无必要修复项；该内部结论不代替用户评价。

## 浏览器行为测试

12 个 Chromium 用例均已覆盖通过，使用实际生产构建、真实图片解码与画布输出。主运行通过 11 项；错误照片用例仍在检查已删除的状态文案所对应的回退状态，将断言改为真实 failure 状态后定向重跑通过。错误提示与原图保留逻辑不变。

## 已接受瓶子的回归检查

以 `2cf32f9` 为冻结基线，在相同 538×460 画布、同一示例照片、暖调、接缝宽度 0.018 和相同渲染环境下，分别比较正面与旋转 0.68 弧度后的实际截图。两组 PNG 均完全一致。

同时逐字比较 `photoCanvas`、暖调装瓶材质、砂体几何、玻璃、瓶塞纹理和相机函数，确认未修改。临时瓶内颗粒、瓶口沙流与二维画框共用迁移时间表，瓶子的稳态渲染受到单独保护。环绕映射未改动，沿用此前四段编号照片的整圈映射检查。

## 平面沙画与材质

平面态继续使用独立的 720×432 二维画布，正面呈现于暖棕画框内。显示尺寸变化只影响 CSS，不重建或投影颗粒。页面使用一个工作台，选照片和主切换按钮在画面上方，旋转与拨沙工具按状态互斥显示在下方；命名输入与标题展示均已删除。页眉短句、介绍副文案、舞台旁白、重复玩法说明、装饰页脚和常驻保存成功提示也已删除；保留必要操作、上传限制、错误提示和一条本地处理说明。

暖调颗粒与交互依据最初 demo。拨沙沿指针路径推动颗粒，旋涡在局部区域施加旋转并逐渐停下。没有自动回原位的弹簧，划痕会保留，只有“聚回照片”明确复原。减少动态效果时仍支持直接操作，旋涡预演缩短，复原立即完成。倒沙耗时 2900ms，装瓶耗时 2800ms。倒出时倾斜真实 3D 瓶子、拔开塞子，让沙流从实际投影瓶口落到画框；装瓶时从当前沙粒位置收拢，经瓶口进入并逐层填满，最后合塞。一份逐粒离开、过瓶口、落地和稳定时间表同时驱动临时瓶内体积、沙流与平面颗粒。落地后从中央局部堆积向下、向两侧滚动；瓶内沙量按经过瓶口的颗粒累计计算。取消时恢复起始状态，页面隐藏时完成到终态，所有临时瓶姿、透明背景和沙流资源均会恢复或清理。减少动态效果时直接抵达相同的完整终态。

装瓶态继续使用紧凑、旋转的不规则颗粒和独立法线切面。砂体贴合内壁并填满瓶肩和瓶颈。玻璃采用本地 HDR 与透明 Fresnel 轮廓近似，没有物理折射或真实沙粒碰撞的承诺。

临时体积的数值检查另覆盖 6000 条迁移路径的事件顺序、结束前稳定和累计沙量，并验证清空采样画布后颜色仍有限、运动颗粒不超出瓶内轮廓、重复切换复用 GPU 缓冲。数值检查不能证明真实物理或视觉自然。
