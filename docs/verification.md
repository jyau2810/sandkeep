# 验收记录

本轮修正连续沙柱、平面提示与画框重叠的问题，并把“聚回照片”改为“复原”按钮，放到“装进瓶子”旁边。平面提示为“轻轻拨动，玩一会儿沙”。静止瓶子的材质、几何、镜头、玻璃和光照继续冻结，装瓶过程保持原样。

## 实际画面

生产构建为 `index-BO10qENP.js`。1440px 桌面、390px 手机模拟、590px 用户面板均采集了八个倒出阶段、完整平面、静止瓶子与装瓶中间帧，没有横向溢出或页面错误。另有 718px 平面截图，直接检查用户指出的重叠，以及两个旋转角度后的倒出样本。

实际连续帧显示细沙分成疏密不同的小股下落，颗粒之间有空隙。落地后先积成小沙堆，再分段滑动并逐渐铺开。画框保持正面矩形，宽度同时受舞台可用高度约束。新提示与外框留出至少 20px；“复原”和主按钮同高并排，540px 以下单独成行。

## 浏览器回归

```text
14 passed (3.2m)
```

本轮先在旧构建 `index-CwCFdUnA.js` 复现。1400ms 时，沙流仅 6 CSS 像素宽，占据其范围内约 84% 的像素，每一行都被填满。718px 宽时，画框与提示重叠约 13px。新的松散沙流回归在旧版失败，结果为 `Expected width >8, Received6`。

新版在 0、72、180 度读取实际沙流画布，检查向下的范围、中心对齐、横向分离、像素密度和行间空隙。稀疏单粒的上下边界允许动画帧采样产生的小幅变化，中心与落点方向仍受严格检查。它不从渲染代码读取预设坐标。

| 行为 | 检查方式 |
| --- | --- |
| 换照片、装瓶与刷新恢复 | 上传生成的 PNG，比较暖调记录、原图和旧记录兼容字段 |
| 拨沙与复原 | 比较原生画布位图，确认划痕保留、缩放不清空、复原准确 |
| 鼠标、键盘和手机触摸 | 检查旋转、拨沙以及手机纵向滚动 |
| 双向转场 | 逐帧检查沙流、沉积面积、装瓶余沙和完成态位图 |
| 转场中换图、调整窗口 | 旧动画不会覆盖新图，最终仍为完整矩形沙画 |
| 松散沙流与旋转方向 | 三个角度检查实际非透明像素的宽度、密度、行空隙及中心 |
| 提示间距与按钮位置 | 1440、900、718、590、390px 检查外框间距至少 20px，两个按钮同高、相邻且无溢出 |
| 格式错误、超大照片与 WebGL 不可用 | 显示恢复入口，并保留已有照片和可用操作 |
| 减少动态效果、存储被禁用 | 制作与直接操作仍可用，保存失败有反馈 |

手机检查属于 Chromium 触屏模拟，软件 WebGL 不代表实际手机硬件性能或所有浏览器版本。

## 沙粒事件与静止瓶子

每粒沙拥有固定的离瓶、落地和稳定时间。出沙间隔属于事件计划，不靠按帧随机擦除颗粒制造。屏幕沙流固定抽样同一批代表颗粒，落地点与平面堆积一致。原生画布的短暂停留和分段滑动在结束前抵达原图位置，结束处理继续恢复准确原画。

数值检查覆盖 85,428 条路线，验证重复编排一致、时间顺序、真实出沙间隔、单调向下、空中与落地交接及精确终点。装瓶时序函数与本轮前的 `bac8f58` 逐字相同。该编排没有模拟真实颗粒碰撞。

受保护的七个瓶子渲染函数保持不变。相同示例、538×460 画布、暖调和渲染环境下，与已认可的 `2cf32f9` 分别比较正面和旋转 0.68 弧度后的瓶子画布；本轮重新运行后，两组 PNG 均完全一致，没有页面错误。

## 素材和复核

四张上架 PNG 和 26 秒正常速度 MP4 已从本轮实际页面重新采集。视频包含旋转后倒出、拨沙、复原、倾斜画框装瓶及再次旋转，没有加速或补绘效果。素材文件均小于 3 MB，PNG 来源元数据完整。

新的独立 Impeccable 复核结果为 `disposition: ship`，没有提出需要修改的项。复核读取了失败基线、三个完成态宽度、718px 平面、连续倒沙与两个录屏取样图。动效判断基于这些连续帧，复核者没有播放原始 MP4。内部复核不等同于用户对新动效的视觉验收。截图和视频只使用代码绘制的猫咪示例，不包含个人照片。
